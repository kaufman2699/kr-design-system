Figma → React Components Tailwind + Storybook

Generate production-ready React components from Figma designs, automatically added to the shared component library with Storybook stories.

Quick Start — 5 Steps to Generate a Component

  1. Copy a Figma frame URL (right-click → Copy link to selection)
  2. Open Claude Code in the kr-design-system project
  3. Paste the URL and say: "Convert this to a React component"
  4. Claude generates the component + Storybook story + updates the barrel export
  5. Run pnpm dev to see it in Storybook at localhost:6006

How It Works

Figma URL
→
Claude Code + Figma MCP
→
React + Tailwind Component
→
Storybook + npm Package

The workflow is automated by a Claude Code skill called figma-to-tailwind. When you paste a Figma URL, it:

Phase What Happens Automatically
1 Discovery Screenshots the design, extracts structure and tokens via Figma MCP
2 Token Mapping Maps Figma colors/spacing to firm-navy, firm-lime, etc.
3 Code Gen Generates TypeScript React component with forwardRef, cn(), variants
4A File Placement Saves to src/components/ui/component-name.tsx
4B Storybook Story Generates .stories.tsx with controls for all variants/sizes
4C Barrel Export Adds the component to src/components/ui/index.ts so it's importable from the package
5 Verification Runs pnpm typecheck + pnpm build, checks Storybook renders

Prerequisites (One-Time Setup)

Follow these steps to set up your machine from scratch. If you already have some of these installed, skip to the next step.

1. Install Node.js (v24)

Download and install Node.js v24 (latest stable) from https://nodejs.org, or use a version manager:

# Using nvm (macOS/Linux)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.0/install.sh | bash
nvm install 24
nvm use 24

# Verify
node --version   # Should show v24.x

2. Install pnpm (Package Manager)

This project uses pnpm for fast, strict dependency management. Install it via corepack (built into Node.js):

# Enable pnpm via corepack (recommended)
corepack enable pnpm

# Verify
pnpm --version   # Should show 11.x

Alternative installation methods:

# Via npm (if corepack is unavailable)
npm install -g pnpm

# Via Homebrew (macOS)
brew install pnpm

# Via standalone script
curl -fsSL https://get.pnpm.io/install.sh | sh -

3. Install Claude Code (AI CLI)

Claude Code is the AI assistant that reads Figma designs and generates components. Install it globally:

# Install Claude Code
npm install -g @anthropic-ai/claude-code

# Verify
claude --version

On first run, Claude Code will ask you to log in with your Anthropic account.

Requires an Anthropic account with Claude Code access. If you don't have one, ask your team lead for an invitation or sign up at https://claude.ai.

4. Clone and Install the Design System

# Clone the repository
git clone https://github.com/kaufman2699/kr-design-system.git
cd kr-design-system

# Install dependencies
pnpm install

This installs React, Tailwind CSS, Storybook, tsup, and all other dependencies.

5. Figma MCP (Automatic — No Extra Setup)

The repo includes a .mcp.json file that configures the Figma MCP connection automatically. When you first use a Figma tool in Claude Code, it will open your browser for OAuth authentication. Just log in to Figma and approve the connection.

# The .mcp.json is already configured:
{
  "mcpServers": {
    "Figma": {
      "url": "https://mcp.figma.com/mcp"
    }
  }
}

No API tokens needed. No Figma Desktop app required. Everything works through the browser.

Generating a Component: Step by Step

Step 1: Get the Figma URL

In Figma (browser or desktop), select the frame you want to convert:

  1. Right-click the frame → Copy link to selection
  2. The URL must include node-id:
https://www.figma.com/design/YOUR_FILE_KEY/FileName?node-id=123-456&m=dev

Important: Select a single frame or component, not the entire page. One frame = one component. For complex pages, convert section by section.

Step 2: Paste into Claude Code

Open Claude Code in the kr-design-system directory and type:

Convert this Figma design to a React component:
https://www.figma.com/design/YOUR_FILE_KEY/FileName?node-id=123-456&m=dev

Or use any of these trigger phrases:

  • "Generate component from Figma: [URL]"
  • "Create React component from this design: [URL]"
  • "Implement this Figma page: [URL]"

Step 3: Watch It Generate

Claude will automatically:

1

Screenshot & Analyze

Captures the design visually and extracts structure, colors, fonts, spacing.

2

Generate Component

Creates a .tsx file following project conventions (TypeScript, forwardRef, cn(), variants).

3

Generate Storybook Story

Creates a .stories.tsx file with interactive controls, all variants, and a link back to the Figma design.

4

Register in Package

Adds the export to src/components/ui/index.ts so other apps can import it.

5

Verify

Runs TypeScript check and build to confirm everything compiles.

Step 4: Preview in Storybook

After generation, launch Storybook to browse and test your new component:

Launch Storybook

pnpm dev

This starts the Storybook dev server. Open your browser to:

http://localhost:6006

1

Find Your Component

In the left sidebar, expand the UI section. Your new component appears alphabetically (e.g., UI / ConfirmDialog).

Click individual stories (Default, Accent, Destructive) or use the Controls panel at the bottom to switch between variants and sizes in real time.

What Gets Generated

For each Figma frame, Claude creates 3 things:

File Purpose Location
component-name.tsx The React component with TypeScript types and Tailwind classes src/components/ui/
component-name.stories.tsx Storybook stories with variant controls and Figma design link src/components/ui/
index.ts (updated) Barrel export so the component is importable from the package src/components/ui/index.ts

Example: Generated Component

// src/components/ui/confirm-dialog.tsx
import * as React from "react";
import { cn } from "../../lib/utils";
import { Button } from "./button";

export interface ConfirmDialogProps extends React.HTMLAttributes<HTMLDivElement> {
  title: string;
  description: React.ReactNode;
  confirmLabel?: string;
  cancelLabel?: string;
  variant?: "destructive" | "default" | "accent";
  onConfirm?: () => void;
  onCancel?: () => void;
}

export const ConfirmDialog = React.forwardRef<HTMLDivElement, ConfirmDialogProps>(
  ({ className, title, description, variant = "destructive", ... }, ref) => (
    <div ref={ref} className={cn("rounded-firm border ...", className)}>
      <h2 className="font-heading text-firm-navy ...">{title}</h2>
      <p className="font-sans text-firm-foreground ...">{description}</p>
      <div className="flex justify-end gap-3">
        <Button variant="outline" onClick={onCancel}>Cancel</Button>
        <Button variant={variant} onClick={onConfirm}>Confirm</Button>
      </div>
    </div>
  ),
);
ConfirmDialog.displayName = "ConfirmDialog";

Example: Generated Story

// src/components/ui/confirm-dialog.stories.tsx
import type { Meta, StoryObj } from "@storybook/react";
import { ConfirmDialog } from "./confirm-dialog";

const meta = {
  title: "UI/ConfirmDialog",
  component: ConfirmDialog,
  tags: ["autodocs"],
  parameters: {
    design: { type: "figma", url: "https://figma.com/design/.../...?node-id=253-1150" },
  },
} satisfies Meta<typeof ConfirmDialog>;

export default meta;

export const Destructive: StoryObj = {
  args: { title: "Delete chat?", confirmLabel: "Delete", variant: "destructive" },
};

Publishing the Package to npm

After generating and reviewing components in Storybook, publish the package to npm so anyone can install it.

First-Time Setup (One per Machine)

1

Create an npm Account

Sign up at https://www.npmjs.com/signup (free). Then create the @kaufman2699 organization at https://www.npmjs.com/org/create.

2

Log In from Terminal

Run this command and follow the prompts:

# Log in to npm

# Follow the browser prompt to authenticate
# Verify you're logged in:
npm whoami

Publishing a New Version

1

Verify the Build

Make sure everything compiles and looks correct in Storybook before publishing.

2

Bump the Version

Update the version number in package.json following semver rules.

3

Publish

Run the publish command — it builds automatically before publishing.

# 1. Verify build works
pnpm build

# 2. Bump the version (choose one)
pnpm version patch    # 0.1.0 → 0.1.1 (bug fixes, small tweaks)
pnpm version minor    # 0.1.0 → 0.2.0 (new components added)
pnpm version major    # 0.1.0 → 1.0.0 (breaking changes)

# 3. Publish to GitHub Packages
pnpm publish

What happens when you run pnpm publish:

  1. Runs pnpm typecheck — blocks if types are broken
  2. Runs pnpm test — blocks if any test fails
  3. Runs pnpm build — produces dist/ (ESM + CJS + types + CSS)
  4. Uploads to npmjs.com as a public package

Consumers install with: pnpm add @kaufman2699/kr-design-system — no .npmrc or tokens needed.

Version Guidelines

Change Type Version Bump Example
Fix a component's styling or bug patch 0.1.0 → 0.1.1
Add new components from Figma minor 0.1.0 → 0.2.0
Rename/remove a component or change its props major 0.2.0 → 1.0.0

Always bump the version before publishing! npm will reject the publish if you try to publish the same version twice. If you forget, you'll see: Cannot publish over the previously published versions. Run pnpm version patch (or minor/major) first.

Don't forget to commit before publishing. Run git add . && git commit -m "feat: add new components" and push your changes. The version bump creates a commit automatically.

Design Token Reference

The converter automatically maps Figma values to these tokens. Designers should use these colors as Figma variables for best results.

Colors

Token Value Tailwind Class Usage
Navy #1E4C7E firm-navy Primary buttons, headings
Lime #AED136 firm-lime Accent buttons, focus rings
Destructive #FF6158 firm-destructive Delete/danger actions
Foreground #4B5563 firm-foreground Body text
Muted #F2F2F2 firm-muted Secondary button backgrounds
Border #E5E7EB firm-border Card borders, dividers
Input Border #C4C4C4 var(--input-border) Outline button borders, form inputs

Typography

Usage Font Tailwind Class
Headings, titles, dialogs Roboto Bold font-heading font-bold
Body text, descriptions Inter Regular font-sans (default)
Buttons, labels Inter SemiBold font-sans font-semibold

Border Radius

Usage Value Tailwind Class
Cards, dialogs, containers 8px rounded-firm
Buttons, inputs, small elements 4px rounded-firm-sm

Tips for Best Results

For Designers (in Figma)

  • Use Auto Layout — it maps directly to Flexbox. Avoid absolute positioning.
  • Use Figma Variables for colors — named variables map to tokens automatically.
  • Name layers meaningfully — "DeleteButton", not "Rectangle 47".
  • Keep components atomic — one frame = one component. Split complex pages into sections.
  • Define all states — if a button has hover/disabled states, create Figma variants for them.

For Developers (in Claude Code)

  • One frame at a time — convert individual components, not entire pages at once.
  • Mention interactions — tell Claude about hover effects, animations, or conditional behavior.
  • Reference existing components — say "use the existing Button" if you see one already in the library.
  • Check Storybook after generation — run pnpm dev to visually verify.
  • Publish after review — run pnpm publish to push to GitHub Packages when ready.

Troubleshooting

Problem Solution
Figma MCP not authenticated Tell Claude: "Authenticate with Figma" — it will open OAuth in your browser
Colors don't match Figma exactly Check if the Figma file uses named variables. Raw hex values may not map correctly. Compare against the token table above.
Component not showing in Storybook Ensure the .stories.tsx file exists and the component is exported from src/components/ui/index.ts
Build fails after generation Run pnpm typecheck to see specific TypeScript errors. Usually a missing import or type mismatch.
Component too large (>500 lines) Convert smaller frames individually. Tell Claude to split into sub-components.
Fonts look wrong Ensure consumer apps load Inter + Roboto from Google Fonts (or the pre-built styles.css which includes the import).
Can't install package in another app Make sure the package is published: run pnpm publish from the design system repo. Then pnpm add @kaufman2699/kr-design-system in your app.

Quality Checklist

After generation, verify:

  • Component uses design tokens (no hardcoded hex — use firm-navy, not #1E4C7E)
  • Uses font-heading for titles and font-sans for UI text
  • Buttons use rounded-firm-sm, cards use rounded-firm
  • All classNames wrapped with cn() utility
  • TypeScript interface defined, component uses forwardRef
  • Storybook story has tags: ["autodocs"] and Figma URL in parameters
  • Export added to src/components/ui/index.ts
  • pnpm test passes (all unit tests green)
  • pnpm build passes without errors
  • Visual output in Storybook matches Figma screenshot
