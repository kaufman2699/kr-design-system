Figma to React Components Tailwind

A designer's guide to converting Figma pages into production-ready React components

How It Works

Figma Design
→
MCP Tools
→
React + Tailwind
→
Production Component

What you'll get: A fully typed React component using Tailwind CSS utility classes, matching the project's design token system and component patterns. No CSS files, no inline styles — just clean utility-first components.

Prerequisites

  • Figma Desktop App (not browser) with Dev Mode access
  • Claude Code CLI installed and configured
  • Node.js 18+ with the project cloned locally
  • Access to the project's Figma design file

One-Time Setup

Step 1: Enable Figma Dev Mode MCP

1

Open Figma Desktop

Launch the Figma desktop app and open the project's design file.

2

Enable Dev Mode

Toggle Dev Mode using the switch in the top-right toolbar (or press Shift+D).

3

Install Dev Mode MCP Plugin

In Figma, go to Plugins → Search and find "Dev Mode MCP". Install and enable it. This starts a local server on port 3845.

4

Verify Connection

In your project's .claude/settings.json, add the MCP server config (see below). Then ask Claude to call get_metadata on a selected element to confirm connectivity.

MCP server config — add to your project's .claude/settings.json:

{
  "mcpServers": {
    "figma-dev-mode": {
      "type": "http",
      "url": "http://127.0.0.1:3845/mcp"
    }
  }
}

Step 2: Authenticate Figma MCP (OAuth)

1

Start Auth Flow

In Claude Code, type: "Authenticate with Figma". Claude will provide an authorization URL.

2

Complete Login

Open the URL in your browser and log in to Figma. Approve the MCP connection.

3

Confirm

If the redirect page shows an error, copy the full URL from your address bar and paste it back to Claude.

Note: The Figma Dev Mode MCP requires the Figma Desktop app to be open with Dev Mode active. If you close Figma, the local server at http://127.0.0.1:3845 will stop and tools will be unavailable until you reopen it.

Converting a Page: Step by Step

Phase 1: Share the Design

Copy the Figma URL of the page or frame you want to convert. The URL must include the node-id parameter:

https://figma.com/design/ABC123/MyFile?node-id=45-678

To get this: right-click the frame in Figma → Copy link to selection.

Then paste it to Claude Code with a request like:

"Convert this Figma page to React components: [paste URL]"

Phase 2: Automatic Extraction

Claude will automatically run these MCP tools in sequence:

Tool What It Does
get_screenshot Captures the visual reference for comparison
get_variable_defs Extracts design tokens (colors, spacing, typography)
get_code_connect_map Checks which Figma components already have code equivalents
get_design_context Generates React + Tailwind code from the design

Phase 3: Code Generation

The raw generated code is transformed to match the project's conventions:

Convention What Claude Applies
TypeScript Typed props interface extending HTML attributes
cn() utility All classNames wrapped for merge support
Design tokens Hex colors replaced with firm-navy, var(--border), etc.
forwardRef Base components support ref forwarding
Variant pattern Visual states defined as variantClasses object
Icons Replaced with <Icon name="..." /> component

Phase 4: Visual Verification

After implementation, Claude will:

  1. Run npm run build to verify no TypeScript errors
  2. Compare the rendered component against the Figma screenshot
  3. Check responsive behavior at mobile / tablet / desktop
  4. Verify hover, focus, and disabled states

When designing in Figma, use Auto Layout. Here's how it translates:

Tips for Better Conversions

In Figma

  • Use Auto Layout everywhere — it maps directly to Flexbox. Absolute positioning requires manual adjustment.
  • Name your layers meaningfully — layer names become component/variable names in code.
  • Use design variables — color/spacing variables map to Tailwind tokens automatically.
  • Keep components atomic — small reusable pieces convert more reliably than giant monolithic frames.
  • Define all states — create variants for hover, focused, disabled, and active states.

When Requesting Conversion

  • Share frame-level URLs — not the whole page. One frame = one component.
  • Specify interactions — mention hover effects, click behavior, animations that aren't visible in the static design.
  • Flag responsive needs — tell Claude if the layout should change at mobile/tablet breakpoints.
  • Reference existing components — say "use the existing Button component" if you see one already in the codebase.

Quality Checklist

After conversion, verify these items are met:

  • All colors use design tokens (no hardcoded hex values)
  • All classNames use the cn() utility
  • TypeScript interface defined for component props
  • Component uses forwardRef with displayName
  • <Icon> component used (no raw SVGs)
  • File is under 500 lines
  • Visual output matches the Figma screenshot
  • Responsive layout verified (mobile / tablet / desktop)
  • Hover, focus, and disabled states work correctly
  • npm run build passes without errors

Troubleshooting

Problem Solution
MCP tools not available Ensure Figma Desktop is open with Dev Mode enabled. Check that the MCP plugin is running.
Authentication expired Ask Claude: "Re-authenticate with Figma"
Generated code uses wrong colors Ensure your Figma file uses the defined design variables, not raw hex values
Component too large (>500 lines) Share individual sections/frames instead of the entire page at once
Layout doesn't match Ensure Figma uses Auto Layout (not absolute positioning). Tell Claude about any special responsive behavior.
Icons not rendering Check that the icon name matches your project's icon system. Ask Claude to list available icons.

Connecting to Your Project

The kr-design-system plugin is hosted as a Git repository. To connect it to any project, add two settings to the project's Claude Code configuration. No files to copy — Claude Code fetches and caches the plugin automatically.

Installation (One-Time per Project)

1

Open Your Project's Settings

In your project root, open (or create) the file .claude/settings.local.json

2

Add the Marketplace + Plugin

Paste the following JSON. This tells Claude Code where to find the plugin and enables it:

{
  "extraKnownMarketplaces": {
    "kr-design-system": {
      "source": "github",
      "repo": "kaufman2699/kr-design-system"
    }
  },
  "enabledPlugins": {
    "figma-tailwind@kr-design-system": true
  }
}

How it works:

  • extraKnownMarketplaces — tells Claude Code about the Git repo that contains plugins
  • "kr-design-system" — the marketplace name (must match the name field in the repo's marketplace.json)
  • "figma-tailwind@kr-design-system" — the plugin name @ marketplace name
3

Restart Claude Code

Start a new Claude Code session in the project. Claude will fetch and cache the plugin. The figma-to-tailwind skill appears in the available skills list automatically.

4

Verify

Ask Claude: "What skills do you have for Figma?" — it should mention figma-to-tailwind.

Private repo? If the kr-design-system repository is private, ensure your Git credentials (SSH key or token) have read access. Claude Code uses your local Git configuration to clone the repo.

What the Skill Does

Once installed, the figma-to-tailwind skill automatically:

  1. Discovers project tokens from tailwind.config.js and global CSS
  2. Runs the MCP extraction pipeline (screenshot → tokens → code connect → design context)
  3. Transforms generated code to match project conventions (TypeScript, cn(), variants, forwardRef)
  4. Maps Figma variables to the correct Tailwind utility classes

Trigger Phrases

The skill activates when you say any of these to Claude Code:

  • "Convert this Figma design to React"
  • "Generate components from Figma"
  • "Extract Figma to Tailwind"
  • "Create React component from design"
  • "Implement this Figma page"
  • Or simply paste a Figma URL and ask for code

Token Audit Script

After installation, run the audit script to check for gaps between your CSS custom properties and Tailwind config:

# From your project root (after plugin is cached):
bash ~/.claude/plugins/cache/kr-design-system/*/skills/figma-to-tailwind/scripts/audit-tokens.sh .

This reports any CSS variables not referenced in tailwind.config.js and lists all color extensions.
